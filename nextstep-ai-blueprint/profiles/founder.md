# User Cognitive Profile — Phase 1 (Static)

This profile is injected into the Insight Agent prompt as context about the user.
In Phase 2, this gets replaced by dynamically derived maps.

---

## Strengths
- Building conceptual frameworks and strategic thinking
- Detecting contradictions and structural weaknesses in ideas
- Thinking from frameworks down to details (top-down reasoning)
- Understanding technology from a product perspective (not implementation)
- Multi-model critique: uses GPT, Gemini, and Claude to stress-test ideas
- Strong at identifying gaps between vision and execution

## Known Gaps
- Direct programming implementation
- Resolving the boundary between ambition and execution scope
- Tendency to over-document and under-test
- May design systems that are architecturally elegant but hard to build incrementally

## Hidden Assumptions to Watch
- Tends to assume complete understanding is required before starting action
- Trusts analysis more than experimentation
- May treat documentation as progress when the real test is building
- Can design five-layer systems when a two-layer system would prove the same hypothesis

## Communication Style
- Mixes Arabic and English naturally (Arabic for deep conceptual work, English for technical terms)
- Prefers framework-first explanations — wants the big picture before details
- Values directness over cushioning — prefers "this won't work because..." over "this is interesting but..."
- Builds arguments from structure to details, not from examples up

## Decision Pattern
- Deliberate — needs the full picture before committing
- Strong preference for comprehensive frameworks over incremental experiments
- When under pressure: may default to more analysis instead of simplifying scope
- Responds well to: "this specific step is clear — start here, test, then expand"

## Work Domains
- AI product design and architecture
- Coaching and personal development frameworks
- Knowledge management and cognitive systems
- Strategic planning and framework design

## What Insight Agent Should Watch For
1. When the user is designing something that could be tested simpler
2. When a question reveals a gap the user doesn't know they have
3. When a new decision contradicts a prior one (check context)
4. When the user is in "analysis mode" but should be in "build mode"
5. When adjacent domains (legal, technical implementation, user research) are missing from the picture
